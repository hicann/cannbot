# README 与 QUICKSTART

## 模块范围

插件根目录的 `README.md` 和 `QUICKSTART.md`，以及它们引用的使用与设计资料。

## 设计思想

两份文档分别回答“这个工作流是什么、为什么这样设计”和“如何安装并开始使用”，共同描述同一个实际可用的工作流，避免维护两套重复的操作说明。

### README.md：新特性、设计与功能

README 按以下顺序组织：

1. **新特性**：放在文档最开头，即标题后的首个内容部分，介绍当前新增或有重要变化的能力及用户可见影响。只描述已实现的特性，不将规划写成已经支持。
2. **设计思想**：说明工作流的目标、PM 与子 Agent 的分工、围绕 harness 的组织方式，以及仓库知识分层等核心设计。
3. **支持的功能**：介绍适用场景、能力范围和实际限制，并提供 QUICKSTART 的入口。
4. **结构组织**：放在靠后的位置，介绍目录、组件职责与相互关系，帮助维护者定位实现。

README 中安装与操作细节链接到 QUICKSTART，避免复制完整教程。

### QUICKSTART.md：安装与使用

QUICKSTART 面向第一次使用工作流的人，给出从准备环境到开始任务、查看结果的操作路径：

- 安装前提与必要输入。
- 实际支持的安装方式、命令参数及目标项目目录。
- 安装后的入口、角色和 Skill 如何在所用客户端中使用。
- 发起任务的示例、需求对齐过程，以及启动、查看结果和恢复的基本方法。
- 子仓需要覆盖 `repo-*` Skill 时的使用入口。

说明以实际支持的客户端与安装方式为准，不把某一个客户端的路径、文件格式或命令当成所有客户端的通用行为。详细设计链接回 README 或对应设计资料，不在快速入门中重复展开。

## 为什么运行说明与设计理由分开

执行任务需要的是能力入口、操作约定与交付要求，维护任务需要的是设计目的和变更边界。父仓、子仓、替换原则等架构解释放在 README 或维护资料中，不要求执行者为完成一个节点读完整套设计历史。

Skill 入口保留必要的框架、基础概念和资料路由，细节按需加载；维护 Skill 的工作区结构与基础设计思想保留在入口，避免读者尚未建立概念就被要求跳转。触发条件写在元数据中，正文不重复说明何时加载。

每条知识保留明确的权威来源，其他资料引用它而不是复制全文。开发者和 Agent 共享的仓库知识优先维护在仓内文档，具体分层见 [repo-* Skills](repo-skills.md)。示例只引入理解规则所需的背景，不让读者为了读懂示例额外调查无关领域。

## 维护方法

**每次维护工作流，都必须检查 README 与 QUICKSTART 的一致性，即使本次修改没有直接涉及文档。** 检查应结合本次变更及真实实现：

- 两份文档是否存在，职责和内容顺序是否符合上述约定，交叉链接是否有效。
- README 的新特性、支持功能和限制，是否与当前实现及 QUICKSTART 的使用方法一致。
- 安装前提、客户端支持、命令参数、路径、Skill 和角色名称是否仍准确。
- 工作流入口、节点组织、交付位置或恢复方式发生变化后，相关说明和示例是否同步。
- 子仓同名 Skill 覆盖方式与实际安装行为是否一致。

发现不一致时同步修订对应文档；检查后无需修改则保留原文，不为满足检查要求制造文档差异。新增用户可见能力时更新 README 开头的新特性说明，并在影响安装或使用时同步更新 QUICKSTART。

文档中的支持声明必须有实现依据。命令或执行示例仅在实际验证后才能描述为已验证，不能把模拟执行、文档检查或启动成功写成完整功能验证通过。
