# Scope Reduction

目标是在保留症状的前提下找到最小 Node/Rank/Step/模型/配置范围，而不是追求最快结束。

## 阶段进入与完成门禁

Primary 在 Preflight 后必须派发 Scope Reducer；“不要求机械执行全部候选”只表示按证据选择最小实验集，不表示可以跳过本阶段。
Scope Reducer 至少完成并落盘：

- 原始稳定复现配置 R0 及其复现契约；
- 当前 Node/Rank/Step/模型/配置范围，以及已有的最近可复现/首次不复现边界；
- 至少一个基于证据的候选及其信息增益、成本、风险和取舍，或没有安全/有信息量候选的明确理由；
- 本轮实际执行、待批准、被拒绝、不可用或无需执行的实验，以及下一阶段可依赖的范围边界。

当前已经是最小复现时，可在完成上述评估后记录 `SCOPE_SKIPPED`；用户拒绝或资源不足时分别记录 `SCOPE_DECLINED` 或阻塞原因。
这些状态只跳过候选实验执行，不跳过 Scope Reducer Agent、`scope_record.md` 或阶段 handoff。缺少该记录时不得进入 Symptom Agent。

## 通用规则

1. 固定原始可复现配置 R0。
2. 每个实验只改变一个因素，并提前写明假设、成本、命令和回退；多节点新作业还要记录 execution mode、scheduler/job 或 handoff、唯一 run/attempt、共享产物根和预期 Node × global Rank。
3. 复现则保留更小范围；不复现则回退上一状态，并以同一契约复跑 R0′，确认症状恢复后再试下一个因素。
4. 记录最近可复现点与首次不复现点，例如“4 层复现、3 层不复现”。
5. 每次不固定 Step 但每次出现仍算稳定复现，记录 Step 分布和观察窗口。
6. 多节点实验只有共享存储与现场启动方式已确认且获批时才能执行；`pssh` 仅在现场命令、host 清单和 runbook 已验证时使用，
   不编造调度器、SSH、host 或 rendezvous 命令。

## 候选顺序

候选顺序必须由现场症状和已有证据决定，不使用固定优先级。Scope Reducer 先结合首发症状、当前范围与边界、Preflight 差异、
并行拓扑、候选适用性、信息增益、成本和风险形成有依据的候选顺序并写入 `scope_record.md`，再优先选择排序最前且可执行、已获批的
单变量实验。不要求机械执行全部候选；新证据需要改变顺序时，先更新排序和理由再继续实验，不得无记录地忽略已有顺序。

以下是候选池，排列本身不表示优先级：

- 减少模型层数，保留最后可复现边界。
- 关闭 activation checkpoint/recompute，尤其需要判断前向还是反向首先出现精度异常的情况下。
- 缩小专家数并同步减小 EP；保持 `expert_count > topk`，必要时单独规划 top-k 实验。
- 按 Node/Rank 递归二分；一半复现则继续该半，均复现或均不复现时记录结果并选信息量最大的下一步。
- 设置 `ASCEND_LAUNCH_BLOCKING=1` 观察全局串行下发影响，或只在已定位的候选边界增加显式同步；两者必须分成独立实验。
- 关闭 compile/graph 模式。
- 开启或关闭 MoE 负载均衡。
- 条件式设置 `LR=0`：保持相同初始权重和输入，并确认参数确实未更新，用于区分当前 forward/input 已存在偏差，还是此前
  backward/update 累积产生偏差。该实验改变训练语义，只是边界观察，不能直接证明 Optimizer 为根因。

这些动作可能改变数值路径、内存、时序或通信，全部视为实验变量，不视为修复。
CPU 替代需要先定位具体 API/Module，不属于 Scope Reduction 候选。

## 最小算子/通信脚本不复现

最小脚本缺少整网通信/计算并发、内存竞争或上下文状态时，负结果只降低候选置信度，不证明候选安全。回到最后稳定复现的整网
R0，按信息增益选择一个因素：

- 关闭一个有现场证据支持的高关联特性开关；
- 比较全局 `ASCEND_LAUNCH_BLOCKING=1` 与候选边界显式同步，但每轮只能选择其中一个；
- 在保留可疑路径的前提下降低拓扑或并发；
- 剪裁已确认低风险的模块，同时保持输入 shape、数据流和训练语义有效。MoE 共享专家或 MLP 只是可能的现场候选，不是默认先剪对象。

每个 R1 都必须回退并复跑 R0′。全局串行下发后症状消失，只能把怀疑范围收敛到跨算子时序或并发上下文，不能当作修复；
症状不变也不能排除算子内部竞争。将结果和下一轮假设交回原路由的 Symptom Agent。

## 失败与回退

- 启动失败、OOM、超时与“症状不复现”分开记录。
- 作业重试使用新 attempt；不得用前后 attempt 拼接 Rank 或复现结果。
- 回退后先以原契约验证 R0′ 回到上一可复现状态；否则状态污染，后续实验无效。
- 不用 Git 破坏性命令回退用户工作区；使用记录的配置副本、显式开关或小补丁。
