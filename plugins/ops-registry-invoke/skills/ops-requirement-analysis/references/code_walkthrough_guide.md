# 代码走读编写指南（code_walkthrough.md）

## 组织方式

按**调用链路**组织章节，自上而下：

```
aclnn API → 算子声明（OpDef / REG_OP）→ Shape 推导 → Tiling → Kernel → 框架适配（op-plugin / Torchair）
```

每章贴关键代码片段 + 内联注释，片段须标注 `文件路径:行号范围`。
省略版权声明、include、日志等非核心代码；简单赋值/API 调用可跳过；复杂逻辑必标注。

## 注释前缀（6 种）与标注原则

| 前缀 | 用途 | 前缀 | 用途 |
|:-----|:-----|:-----|:-----|
| `// 功能：` | 代码块核心功能 | `// 条件：` | 分支触发条件 |
| `// 输入：` | 数据来源 | `// 安全：` | 并发安全、边界防护 |
| `// 输出：` | 数据去向 | `// 注意：` | 非直观设计细节 |

注释**内联**在对应代码行旁，禁止代码块结束后集中注释；代码块之间加一两句过渡说明。

## 变体全量覆盖（强制）

Tiling 策略和 Kernel 模板的总体规格表列出 N 个变体，则下方必须为**每一个**变体生成对应详细分析子章节
（计算流程 + Buffer 分配 + Tiling 策略）。禁止只分析"主要"或"典型"变体，禁止用"结构同模板 1"跳过。

## 示例

```cpp
// 行号: 372-375, 文件: op_kernel/fast_gelu_v2.h
Adds(tmp1, xCompute, 1e-12);   // 功能：加 epsilon 防除零
Abs(tmp2, tmp1);               // 功能：取绝对值，sgn 分母
Div(sgn, tmp1, tmp2);          // 输出：sgn = (x+ε)/|x+ε|
```
